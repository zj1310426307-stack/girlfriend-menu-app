# LoveOS V3 游戏性能审计

审计日期：2026-08-17

## 环境

`scripts/benchmark_v3.py`，Windows 本地、FastAPI TestClient、隔离 SQLite；不是 Render 托管延迟，也不代表微信真机渲染帧率。

## 本轮实测

| 指标 | 样本 | Mean | P95 | 门槛 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| `/api/bootstrap` | 30 | 61.431 ms | 77.700 ms | 300 ms | PASS |
| 旧首页三个请求 | 30 | 107.342 ms | 122.145 ms | 参考 | PASS |
| 五子棋 strategy AI | 100 | 0.554 ms | 0.648 ms | 100 ms | PASS |
| 实时房间内存创建 | 100 | 0.029 ms | 0.038 ms | 300 ms | PASS |
| 快照恢复 | 100 | 0.073 ms | 0.094 ms | 3000 ms | PASS |
| 回放 JSON 序列化 | 100 | 0.064 ms | 0.106 ms | 1000 ms | PASS |

## 瓶颈判断

- 本地规则、AI、快照编解码均远低于预算；
- 托管房间创建和重连仍包含网络、数据库、冷启动与可选 Redis，必须在部署授权后单独采集；
- 飞行棋渲染能否满足目标必须由微信开发者工具和真机验证，后端微基准不能替代。
