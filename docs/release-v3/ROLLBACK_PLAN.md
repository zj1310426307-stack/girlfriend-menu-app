# LoveOS V3 回滚方案

更新日期：2026-08-28

## 原则

优先前滚修复，或回滚应用代码但保留数据库 head。旧应用可忽略 V3 新增表，这是比直接降库更安全的默认路径。

## 发布前记录

- 生产当前 Render deploy ID 与 commit SHA。
- 生产 Alembic revision。
- 备份文件名、UTC 时间、SHA-256 与核心表行数清单。
- 微信当前稳定版本号与可回退的构建记录。

## 触发条件

- `/api/health` 或 `/api/ready` 持续失败。
- 登录、身份恢复、点单、订单状态、撤回或评价出现数据破坏风险。
- WebSocket/游戏出现不可恢复的连接或结算错误。
- 迁移 revision 与候选不一致，或生产出现明显错误率/延迟回归。

## 应用回滚

1. 暂停继续发布与微信审核操作。
2. 在 Render 重新部署发布前已记录的稳定 deploy/commit。
3. 保留数据库 `20260817_14`，执行健康、认证、点单和 WebSocket 冒烟。
4. 若回滚应用不能恢复，再进入数据库处置评审。

## 数据库回滚

只有在备份已验证，且确认没有需要保留的微信绑定和管理审计数据时，才允许从 `20260817_14` 降至 `20260817_13`。降级会删除 `wx_users`、`admin_accounts`、`admin_auth_events`，因此默认禁止在生产直接执行。执行前必须再次核对目标 URL 不是 staging、恢复库或本地库，并由发布负责人确认。

## 小程序回滚

重新上传/发布上一稳定版本，不删除用户本地 `gf_customer_id`；该值仍是旧身份恢复桥梁。后端接口保持旧端点兼容，bootstrap 与微信 session 不可用时客户端按既有回退路径运行。
