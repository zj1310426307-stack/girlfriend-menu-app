# LoveOS V3 架构审计

审计日期：2026-08-17
审计分支：`feature/loveos-v3-refactor`
基线提交：`641c0d612d2c5b77e731e43271e0b6462fdb52b9`

## 结论

当前仓库已经具备可继续演进的生产骨架，并不是需要推倒重建的单体项目。后端已有 FastAPI Router、Service、Repository、纯游戏规则层、运行时状态管理、Redis 可选能力、数据库迁移和 OpenTelemetry 基础；小程序已有统一 HTTP 入口、独立 WebSocket 客户端、页面级按需数据读取和 CI 契约测试。

V3 应采用增量迁移：保留公开 URL、数据表和稳定业务流程，在内部增加插件注册、统一 AI 策略、启动聚合接口、前端模块边界与契约护栏。为了得到新的目录外观而复制现有能力，会制造第二套真相源，已明确排除。

## 前端审计

### 已确认的良好边界

- 业务页面没有直接调用 `Taro.request`；HTTP 请求集中在 `src/api/index.js`。
- WebSocket 分为管理员、统一游戏、骰子和五子棋客户端，页面未自行创建裸连接。
- `app.jsx` 不在启动时预取游戏、历史、通知或 AI 数据。
- 首页只并发读取菜品、收藏排行和情侣积分；其余模块在进入页面后加载。
- 菜品图片已使用小程序 `lazyLoad`，上传端已有 Pillow 依赖可复用。

### 主要问题

1. `src/api/index.js` 约 18.5 KB，承载全部领域方法，变更冲突和认知负担偏高。
2. 31 个页面全部进入主包；游戏、后台和情侣二级页没有通过 `subPackages` 隔离。
3. 游戏页面和渲染文件是体积热点：飞行棋、骰子、斗地主、象棋、五子棋均明显大于普通页面。
4. 路由字符串散落在页面和组件中，移动到分包时容易漏改。
5. 当前前端为 JavaScript，不能直接获得 OpenAPI 生成 TypeScript 客户端的编译期收益；需要先建立可重复导出的 OpenAPI 契约，再分阶段迁移。

### 重复与无效代码判断

- 棋盘组件在视觉和交互语义上不同，不应仅因文件相似就强行合并。
- 各游戏页面都包含房间创建、加入、同步和恢复流程，适合抽取“会话控制器/Hook”，但必须保持每个游戏的规则和 UI。
- 暂未发现可以在没有行为证据的情况下安全删除的前端文件。删除动作延后到引用扫描、构建和页面验收同时通过之后。

## 后端审计

### 已确认的良好边界

- `main.py` 只负责应用组装、生命周期、中间件和后台任务。
- 业务路由已拆到 11 个领域模块。
- Repository 层和纯游戏规则层已有 import-linter 契约；基线为 `2 kept, 0 broken`。
- `games/core/engine.py` 已提供统一 `GameEngine`、规则异常和状态序列化契约。
- 游戏结算已有幂等状态机，支持失败重试并避免重复奖励。
- 生产迁移由 Alembic 负责；本地兼容建表逻辑被环境条件限制。

### 主要问题

1. `api/routes/games.py` 仍直接编排多个顶层 `*_service.py`，游戏类型扩展依赖修改路由文件。
2. `game_runtime/manager.py` 约 35.8 KB，连接管理、房间运行时和协议分发职责较重。
3. `models.py`、`schemas.py`、`crud.py` 仍是跨领域大文件；新式 Repository/Service 与旧式顶层服务并存。
4. `ai/` 有统一基类，但多个文件只是对 `games/*/ai.py` 的兼容转发，缺少统一注册和能力描述。
5. 应用元数据仍显示 `2.11.0`，与包版本 `2.11.2` 不一致。

## 迁移边界

### 本轮允许

- 在现有 `games/core` 上增加注册表和插件描述，不复制一个新的游戏核心。
- 在现有 `ai` 上增加策略能力注册和统一调用入口，保留旧导入路径。
- 增加 `/api/bootstrap`，旧接口继续可用。
- 拆分前端 API 门面，原导出继续兼容。
- 以路由常量和分包兼容测试为前提逐步分包。
- 为现有图片服务增加可选缩略图/WebP 能力，不改变旧图片 URL。

### 本轮禁止

- 删除旧 API、旧数据表或迁移历史。
- 直接用新框架替换飞行棋，除非微信运行时 PoC、许可证、体积和功能适配全部通过。
- 引入第二个 Node/Bun 实时服务器来替代现有 FastAPI WebSocket。
- 重新设计游戏规则、积分结果或 UI 行为。
- 在没有可重复测量的情况下宣称“首屏小于 2 秒”。
