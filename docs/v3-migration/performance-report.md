# LoveOS V3 性能报告

验证日期：2026-08-17

## 测量边界

本报告的 API 数据来自本地 FastAPI TestClient + 隔离 SQLite，AI 数据来自固定五子棋局面；它们不是 Render/PostgreSQL 托管延迟。小程序包体来自 Taro 生产构建。微信启动时间尚未在体验版真机采集，因此不能声称 `<2s` 已达标。

## 首页 API

30 轮本地测量：

| 路径 | 平均 | P95 |
| --- | ---: | ---: |
| `/api/bootstrap` | 18.962 ms | 22.396 ms |
| 三个旧首页请求合计 | 33.222 ms | 35.602 ms |

本地 ordinary API P95 预算为 300 ms，bootstrap 通过。它把首页所需数据减少为一个网络往返；旧接口仍作为部署窗口回退。托管 P95 仍需 Phase 3.1-A 证据采集确认。

## 本地 AI

五子棋 `strategy` 固定局面 100 次：平均 0.514 ms，P95 0.578 ms，低于 100 ms 本地规则 AI 预算。该指标不包含大模型、网络或 UI 渲染。

## 微信小程序包体

| 指标 | V2 基线 | V3 | 变化 |
| --- | ---: | ---: | ---: |
| 主包 | 803,033 bytes | 484,291 bytes | -318,742 bytes（-39.7%） |
| 分包 | 0 | 379,823 bytes | +379,823 bytes |
| 总包 | 803,033 bytes | 864,114 bytes | +61,081 bytes（+7.6%） |
| 文件数 | 137 | 182 | +45 |

15 个 Taro 原生分包把重游戏与管理页移出首次主包。总包增长来自分包共享块重复，属于已知代价；后续应以微信“分包异步化/独立分包”实际行为和真机缓存数据决定是否继续合并分包根。

## 图片

上传仍保存兼容原图，同时用现有 Pillow 生成最长边 960px、quality 82 的 WebP 缩略图。新管理端优先保存缩略图 URL；旧客户端与旧图片 URL 不变。对象存储/CDN 继续复用已有 S3-compatible public base URL，本轮没有修改线上 CDN 配置。

## 启动目标

`<2s` 当前状态：**待体验版真机验收**。应用启动没有一次加载游戏列表、历史、成就、通知或 AI 数据；首页采用骨架/缓存和 bootstrap，但只有发布后的冷启动/热启动各至少 10 次、记录机型与网络，才能签署该指标。
