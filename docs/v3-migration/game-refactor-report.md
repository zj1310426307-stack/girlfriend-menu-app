# LoveOS V3 游戏重构报告

验证日期：2026-08-17

## 已完成

### 可发现插件

`GamePluginRegistry` 现在集中描述 6 个服务端游戏：骰子、五子棋、飞行棋、斗地主、斗兽棋和中国象棋。描述包含稳定类型、旧别名、人数、模式、AI 难度、回放能力、引擎工厂和旧 API 前缀。注册表构造后不可变，重复标识会在启动/测试阶段失败。

游戏目录 seed 和通用房间人数均来自同一注册表。数据库仍允许保存 `coming_soon` 等尚未安装运行时插件的目录项，保持原有扩展语义。

### AI 解耦

`AIProviderRegistry` 统一 5 类本地游戏 AI 的能力发现、难度校验、人设目录和耗时记录。五子棋运行时已通过注册表选动作；旧 `ai/*.py` 导入路径和具体算法继续可用。规则动作完全在本地完成，不调用远程大模型。

### 兼容 adapter

通用重连不再在 API 路由里维护散落的游戏类型条件，而由 `game_compatibility_service` 路由到原权威状态源。公开 HTTP、WebSocket、规则、积分、回放和数据库字段未改变。

## 飞行棋决策

本轮没有把 Phaser 加入生产依赖，也没有删除现有飞行棋。Phaser 是面向浏览器 Canvas/WebGL 的渲染框架，不是包含 LoveOS 服务端房间、规则、事件、任务和积分的 Ludo 引擎；在微信小程序真机兼容、触控、后台恢复和包体积未通过 PoC 前直接替换不满足生产安全要求。

当前飞行棋以 `aeroplane` 插件描述并通过 `flight` 旧别名、旧接口及原 `flight_service` adapter 运行。LoveOS 爱心事件、情侣任务、随机互动和默契积分保持不变。真正的开源渲染器替换仍是独立发布门槛，不能标记为完成。

## 架构边界证据

import-linter 当前结果为 `5 kept, 0 broken`：

- Repository 不依赖 API/Service 编排。
- 纯游戏规则不依赖 Web 或持久化框架。
- API 不直接进入 Repository 内部。
- Service 不依赖 HTTP 表现层。
- 本地 AI 不依赖 Web 或持久化框架。

插件、别名、引擎恢复、AI 动作以及重连 adapter 均有 V3 专项测试。完整游戏测试和完整后端测试通过。
