# V2.3 双人五子棋系统

## 产品范围

V2.3 在“一起玩”中开放双人实时五子棋，不改变点菜、订单、评价、大话骰或管理端原有流程。玩法固定为两台设备、15×15 棋盘、黑方先手、任意方向五子或更多连珠获胜。

页面入口：

- `pages/games/index`：创建棋局、输入房间码快速加入。
- `pages/games/gomoku/index`：房间、玩家席位、回合提示、棋盘、结算和再来一局。
- `pages/couple/game-records`：当前设备的历史游戏记录。
- `pages/admin-stats/index`：管理端游戏统计。

## 服务端权威规则

规则引擎位于 `backend/gomoku.py`，不依赖 FastAPI、数据库或 WebSocket，便于独立测试。棋盘使用 `board[y][x]`：

- `0`：空位。
- `1`：黑棋。
- `2`：白棋。
- 第一位加入的玩家固定为黑方，第二位为白方。
- 只有 `turn_id` 对应玩家可以落子。
- 坐标必须是 `0`～`14` 的整数，布尔值不作为整数接受。
- 已占用格点不能重复落子。
- 服务端分别沿横、竖、左斜、右斜统计连续同色棋子，达到 5 颗或更多即结束。
- 225 个格点全部落满且无人连成五子时判为和局。

客户端只发送 `{x, y}`，不会提交随机结果、胜者或棋盘快照，因此修改普通客户端不能越过服务端轮次与胜负判断。

## 对局状态

```text
waiting → playing → finished
                  ↘ 双方 rematch → playing（下一局）
```

状态快照包括：

- 15×15 棋盘。
- 玩家 ID、显示名、席位、黑白方、连接状态和房间局分。
- 当前回合、最后落子、落子总数、胜者与和局状态。
- 当前局数、双方是否已申请再来一局。
- 结束后的轻量情侣互动奖励文案。

双方都点击“再来一局”后清空棋盘、局数加一并由黑方继续先手。房间的玩家席位和局分保留。

4. 将 `games.type = gomoku` 的目录状态更新为 `available`。

唯一约束：

- `game_players(room_id, player_id)`：同一设备在同一房间只占一个席位。
- `game_players(room_id, seat)`：同一房间的席位不能重复。
- `game_records(room_id, round_number)`：一局只能保存一条结算记录。

`game_records.result` 保存胜者、和局、落子数、最后一步、结束时房间局分和互动奖励文案；它是结算快照，不用于恢复正在进行的棋盘。

## 情侣积分

结算完全由后端触发：

| 事件 | 对象 | 积分 |
| --- | --- | ---: |
| 完成一局 | 两位玩家 | 每人 +1 |
| 赢得一局 | 胜者 | +5 |
| 连续第三场获胜 | 胜者 | +10 |

参与和获胜分别写入 `GAME_PLAY`、`GAME_WIN`；三连胜写入 `SPECIAL_EVENT`。每条流水以 `game_records.id` 为业务来源，通过唯一约束防止重试造成重复加分。

三连胜按完成时间从最新五子棋记录向前统计；遇到其他胜者或和局即中断。连续胜场数达到 3 的倍数时触发，例如第 3、6、9 场。

## 查询与统计

当前设备历史：

```http
GET /api/games/records/my
X-Customer-Id: gf_device_id
```

返回最近最多 50 条参与记录，按完成时间倒序，包含房间码、局号、游戏类型、胜者、时长、结果和房间玩家。

管理统计：

```http
GET /api/admin/games/stats
Authorization: Bearer <admin_token>
```

返回总游戏次数、五子棋局数、由房间创建者视角计算的五子棋胜率、最常玩的游戏和游戏积分变化。该积分统计包含 `GAME_PLAY`、`GAME_WIN` 以及描述为“五子棋三连胜”的 `SPECIAL_EVENT`，不会把订单再次点单等其他特殊事件误算为游戏积分。

## 实时状态与故障边界

以下内容持久化：

- 房间元数据与完成时间。
- 玩家席位和房间局分。
- 已完成的每局记录。
- 情侣积分流水。

以下内容只保存在当前 FastAPI 进程内：

- 正在进行的棋盘。
- 当前回合和最后落子。
- WebSocket 连接。
- 未结算的局内状态。

因此，短暂断网后在同一服务进程内可用原 `player_id` 重连并复用席位；Render 重启、多实例切换或进程退出后不能恢复未完成棋盘。玩家重新连接时不应把新空棋盘误认为旧局已恢复。跨进程恢复需要后续引入 Redis 或专门的对局状态存储与房间归属策略。

## 兼容性

V2.3 沿用 `/ws/game/{room_code}` 统一协议，不改变已有大话骰消息。旧接口 `/api/games/dice/rooms` 与 `/ws/games/dice/{room_code}` 继续保留，因此旧小程序版本不会因为五子棋上线立即失效。

## 验收清单

1. 两台设备使用不同 `gf_customer_id`，一台创建、一台凭房间码加入。
2. 第一席显示黑棋并先手，第二席显示白棋。
3. 非当前玩家落子、越界坐标和重复格点均收到明确错误，棋盘不改变。
4. 分别验证横、竖、两条斜线五连；结束后不能继续落子。
5. 双方都点击再来一局后进入下一局，棋盘清空且黑方先手。
6. “我们的游戏记录”显示胜负、局数、时长和最近记录。
7. 双方参与积分各 +1，胜者额外 +5；第三场连续胜利额外 +10。
8. 管理统计显示总局数、五子棋局数、胜率、最常玩的游戏和游戏积分变化。
9. 旧大话骰创建、加入、叫骰、开盅和再来一局仍正常。
