# 2.9.2 全游戏质量优化

本轮不新增游戏，目标是让现有玩法规则更完整、AI 难度有真实差异、操作反馈更明确。

## 参考与授权边界

- 五子棋参考 MIT 项目 [shaunak-deo/GomokuAI](https://github.com/shaunak-deo/GomokuAI) 的“先胜、再防、再评估局部棋形”分层，以及 MIT 项目 [JiachenRen/GomokuZero](https://github.com/JiachenRen/GomokuZero) 的威胁搜索思想；本项目独立实现轻量双重威胁评分，没有复制源码。
- 飞行棋参考 MIT 项目 [RoJac88/ludo-js](https://github.com/RoJac88/ludo-js) 的出发、吃子、安全移动和精确到达规则组织方式；沿用本项目服务端骰子和持久化状态。
- 斗地主参考 MIT 项目 [datamllab/rlcard](https://github.com/datamllab/rlcard) 的引擎、合法动作和智能体分层；本项目独立补充连对、飞机、四带二与服务端提示。
- 中国象棋参考 MIT 项目 [xianminx/ai-chinese-chess](https://github.com/xianminx/ai-chinese-chess) 的完整规则校验与 AI 分层；策略档使用有上限的两层搜索，避免拖慢手机请求。
- 3D 骰子继续基于现有 Three.js/Rapier 场景，遵循 MIT 项目 [mrdoob/three.js](https://github.com/mrdoob/three.js) 的帧循环和场景分层实践；本轮只改大话骰概率决策，不引入第三方资源。

只借鉴公开的规则组织、交互模式和算法思路。未直接复制许可证不明确项目的源码、美术或音频。

## 游戏变化

| 模块 | 2.9.2 优化 |
| --- | --- |
| 五子棋 | 策略档识别活三、活四和双重威胁，继续保持服务端权威落子 |
| 飞行棋 | 策略档优先精确到达、吃子和安全进家，并评估下一轮被吃风险 |
| 斗地主 | 新增连对、飞机、飞机带单、四带二；私有状态返回合法出牌提示 |
| 斗兽棋 | 策略档进行一回合反击检查，兼顾进兽穴、吃子、守穴和机动性 |
| 中国象棋 | 策略档增加材料、兵卒推进、中心控制与有上限的两层搜索 |
| 大话骰 | AI 按自己的骰子和未知骰子的二项分布估算叫法可信度 |
| 转盘 | 可开启连续两次不重复，并在本机保留最近 6 次结果 |

## 兼容与隐私

- 不修改点菜、订单、评价、管理端、积分和联机房间接口。
- 斗地主提示只基于当前查看者的手牌和桌面牌，不返回其他玩家手牌。
- 转盘历史和防重复开关只存微信本地缓存，不上传后端。
- AI 的随机分支只影响娱乐决策，所有联机胜负仍由服务端规则引擎判定。

## 验收

发布前至少执行：后端完整 `pytest`、小程序 `npm run build:weapp`、微信开发者工具预览，以及两台真机的创建/加入/断线恢复测试。
